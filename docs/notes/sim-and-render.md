# Simulation, Renderer & Desktop Technical Notes

Durable findings and baseline benchmarks for `desktank-sim`, `desktank-render`, WGSL/Tint/naga, saves, and desktop platforms. Add new notes only when they capture a non-obvious constraint future work must respect.

- Save/load determinism tests only catch divergence a run happens to reach: the light lag after loading (Done, "Light after loading") existed since T8 and surfaced only when an unrelated change moved a fixture's save tick. A caught divergence with equal creatures and cells: compare `state_hash` parts (cells, fields, creatures, plants, masks), then unhashed caches (light, opacity) block by block.
- Per-individual variation from a hash of `(seed, id, salt)` needs no saved state and keeps every species' run independent of the others, which the harlequin/neon isolation test checks exactly; keep each quirk at or under the old constant where a saved counter is validated against it.
- Live food: a live food's eaters come from the diets (its `live_food` material), not from `prey_cm`, so predators never take it through predation and easy mode, which turns predation off, still feeds fish; the sensing snapshot is built while a live food and an eater share the tank. Live food outside the population cap means a full breeding tank can still be fed live; the renderer's sprite limit grew with it rather than letting live food crowd the cap. Anything that stops at the cap must compare `World::stock_count()`, not `creatures().len()` (the `spawn` cheat and `scene::stock` didn't, at first). `WebTank::creatures()` and the bench's creature count stay the total in the tank, live food included. A save that holds a new species (here `live_bloodworm`) can't be loaded by an older build of the same format version: the species table's names mismatch.
- Creature art (issue #46): trace each silhouette from a real photo of the species before shading; generic ellipse-and-triangle shapes and flat fills read as stickers beside the pixel-art fish. Draw fine frames at 4 texels a cell and derive the coarse frames from them, then compare beside the betta and honey gourami at one scale.
- Sub-cell outlines on a cell raster: trimming loose cells by their open neighbours smooths sand and gravel slopes, but rigid circles stay octagons (a radius-10 pour has rows 7, 11, 13, …, 21 cells wide). Shader-only smoothing doesn't fix it: Catmull-Rom through cell centres traces the octagon, and a B-spline 4×4 kernel rounds only about one cell for 16 reads per rock texel. The fix is to record each rigid cell's 4× coverage in the sim (next increment). A world-space texture pattern (the old staggered 5×4 pebbles) reads as sliced when a per-cell contour cuts it; draw per-cell shapes whose edges follow the contour instead.
- O3 macOS event sources: linking `AppKit` directly and calling `NSWorkspace.sharedWorkspace.notificationCenter` via `msg_send!` keeps `Cargo.lock` free of a duplicate `objc2-app-kit` version alongside winit 0.30's `0.2.2`, reusing only the `objc2`/`objc2-foundation`/`objc2-core-foundation`/`block2` versions already locked by `wgpu-hal`. Attaching `IOPSNotificationCreateRunLoopSource` to `CFRunLoop::current()` and making `PowerMonitor` `!Send` guarantees teardown runs on the same run-loop thread that drives `iops_callback` (the main thread in GUI apps, and the test thread in `cargo test`). Never post fake `com.apple.screenIsLocked` to the system-wide `NSDistributedNotificationCenter` in tests — pass fresh local `NSNotificationCenter::new()` instances into `register_observers`. Release measurements (M3 Max): binary 4.8 MB; `desktank window --no-save` settled CPU 0.1–0.4% (`0.02 s` over 5 s), RSS 96.3 MB, `--demo-pour 2` 6.3% CPU; `desktank bench --seconds 30 --fish 30` settled sim tick mean 0.067 ms, RSS 28.3 MB now / 29.5 MB peak.
- Four-texel art keeps crisp texels at the existing even display scales by choosing the two-texel artwork at scales such as 6, where a four-texel pattern would alternate between one and two screen pixels per texel. Plant detail is pure shader logic over the existing species texture: each shape's fine variant overrides the two-texel coverage and shade only when `fine_scale()` holds, so the coarse art is untouched at other scales. Software renderers such as SwiftShader (CI's WebGL2) pay for a branch even when no fragment takes it: with the fine code merely skipped, CI's frames slowed enough to fail the timing-bound `saves.spec.ts` tests at scale 2 (about 6% fewer ticks per second on a throttled local SwiftShader). The renderer now builds a second grid pipeline with the `FINE_PLANTS` override constant false and uses it at scales not divisible by four, so the compiler drops the fine code there, which brings the tick rate back to `main`'s. WGSL reserves many words beyond its keywords (`from` among them; naga rejects it too), so check new identifiers against the spec's reserved list.
- With fine art for all eleven species the sprite atlas is 256×240 texels (240 KiB, 160 KiB of it fine frames), well inside WebGL2 limits, and each sprite instance carries a second frame origin (eight bytes). The `climbing` render scene (80×45 cells at 320×180) is at scale 4, so it is the one reference showing fine creature art; the bench (2560×1440) draws them too.
- naga is laxer than Tint, Chrome's WGSL compiler: it accepts `a * b ^ c`, which WGSL forbids (bitwise operands must be unary expressions). Native tests and the Playwright tests (WebGL2 on SwiftShader, translated to GLSL by naga) never parse WGSL in the browser, so a Tint-only error shows up only as a black canvas on WebGPU. Parenthesise every operand of `&`, `|`, `^`, `<<` and `>>` that is not a single term, and never chain comparisons or mix `&&` with `||`; the `wgsl_precedence` test enforces this without a GPU.
- Lock screens are restricted: macOS allows no custom lock screen and Windows only a picture, slideshow or Spotlight (no live rendering), so "lock screen" mode may mean the screensaver shown while locked.
- Reported, unverified: Windows 11 24H2 broke several wallpaper apps (Microsoft compatibility hold, [The Register](https://www.theregister.com/2025/04/14/windows_11_24h2_hold/)); test wallpaper mode on 23H2/24H2/25H2.
- Reported, unverified: macOS `legacyScreenSaver` (Sonoma–Tahoe) never deallocates `ScreenSaverView`s ([cocoa-dev](https://lists.apple.com/archives/cocoa-dev/2024/Sep/msg00001.html)); see SPEC §3.4 for mitigations.
- GNOME's mutter has at most experimental wlr-layer-shell support, so Wayland wallpaper/overlay target wlroots compositors and KDE first.
- Cargo 1.100 warns on unused dependencies (`cargo::unused_dependencies`). Stub crates keep their SPEC §4.1 dependency edges with `use <crate> as _;`; drop those lines once the crate is really used.
- Dependabot labels 0.x bumps such as winit 0.30 → 0.31 as "minor", so the winit ignore covers semver-minor as well as major.
- Release profile uses `panic = "abort"` (smaller binaries, and a panic across the `.saver`'s `extern "C"` boundary aborts anyway). Revisit if a host ever needs `catch_unwind` to survive a panic.
- Stub release binaries on macOS: `desktank` 0.5 MB, `desktank-saver` 0.3 MB.
- winit 0.31 is still in beta (Nov 2026); use 0.30.
- T1 bench on the dev Mac (Apple Silicon, release): heavy pour 1.43 ms/tick early, 1.56 ms later (budget 5 ms); settled 4 µs (budget 0.5 ms). The pour settles after ~3100 ticks (155 s of world time).
- If two classes can each initiate the same exchange (water falling into a bubble, the bubble rising into water), the pair moves twice per tick and drifts sideways. Only liquids are displaceable; buoyant cells move themselves.
- A liquid that wanders sideways with no drop in reach never settles (chunks stay awake forever). Liquids only move towards a reachable drop, which leaves terraces of one cell per `LEVEL_REACH` columns.
- Diagonal-only powder slides give 45° piles; a per-row run pattern derived from `repose` gives any angle from 15° to 45° exactly.
- Falling-sand engines such as The Powder Toy appear (inferred, unmeasured) to process every live particle each frame; DeskTank must use sleeping chunks + dirty rects and a sim tick below the render rate to meet its budgets.
- T2 numbers on the dev Mac (M3 Max, release; the SPEC reference is an M1 Air): `desktank bench` settled CPU 0.19% of a core, settled tick 0.027 ms, pour CPU 5.4%, pour tick 0.65 ms mean, GPU 0.03 ms mean / 0.16 ms p95 at 2560×1440, RSS 21 MB (offscreen). `desktank window` settled: 0.25% CPU over 60 s; hidden 60 s: 0.00 s CPU, 1 wake-up per 20 s. Window memory: footprint 53 MB (Activity Monitor), but `ps` RSS 90 MB because it counts ~40 MB of clean shared framework pages; the swapchain's IOSurfaces are 29 MB of the footprint.
- wgpu 30: `SurfaceConfiguration` gained `color_space` (use `Auto`), `get_current_texture` returns a `CurrentSurfaceTexture` enum, and `InstanceDescriptor` takes the winit `OwnedDisplayHandle` (needed for GLES on Wayland). Timestamp queries work on Apple Silicon Metal.
- winit 0.30 reports `Occluded` on macOS and X11 but not on Windows or Wayland; Windows minimise shows up as a zero size, and `Window::is_minimized` is polled in `about_to_wait` as a fallback. A window fully covered on Windows, or hidden on Wayland, isn't detected yet.
- Settled ticks cost ~25 µs because the loop still wakes at 20 Hz to tick world time; with zero awake chunks the tick could be skipped or batched once creatures exist.
- T4 numbers (M3 Max, release, 1280×720 pt window at 2560×1440 px): `desktank window --demo-pour 10` used 8.1% of a core over a 10 s continuous pour at the default radius 3 (budget 15%), and 16.5% at the maximum radius 24 (a 49-cell-wide sweep moving far more sand); 0.85% over the next 20 s while the sand settled. RSS 93 MB (as T2).
- Synthetic mouse events (`CGEventPost`) need Accessibility permission for the posting process, which agent shells don't have, so real-input checks in `desktank window` are manual; `--demo-pour` drives the same code paths instead.
- References blessed on Metal (M3 Max); a 5% green cut in the fragment shader fails both scenes (28% and 36% of pixels over ΔE 2, max ΔE 7.9 and 9.8), so the tolerance catches small palette shifts.
- `desktank capture` (debug build) renders 60 frames of 640×360 in ~3.7 s.
- T4b bench (M3 Max): heavy pour 1.43 / 1.55 ms and settled 3.4 µs per tick (unchanged from T1); a radius-12 rock sinking through water 37 µs per tick; a settled tank with 13 resting rocks 3.5 µs.
- T4c bench (M3 Max, same session as `main` at 6589355): heavy pour 1.55 / 1.67 ms (main 1.51 / 1.66), settled 3.70 µs (3.50–3.60), settled with 13 rocks 3.69–3.84 µs (3.56–3.72), all within run-to-run noise; `body_sinking` 17 µs (38 µs), because five ticks after release the accelerating rock has barely started to move.
- A rigid body's glued flag lives in the low bit of the variant byte so the renderer needs no third texture channel: every palette shade range starts on an even byte, so the bit never changes a cell's shade. Driftwood stores per-cell waterlogging (`0..=127`) in the upper seven bits (`variant >> 1`) while keeping bit 0 as `GLUED_VARIANT_BIT`, and updates changed cells via `World::mark_visual` without waking chunks (save format v11 preserves wetness and migrates pre-v11 driftwood to dry).
- T5 bench (M3 Max, criterion): heavy pour 1.48 / 1.62 ms per tick (was 1.43 / 1.55 ms on main: the living-list rescan of changed rects), settled 4.2 µs, settled with bodies 4.2 µs, and a settled tank with fields and random ticks active (a 640×12 aquasoil bed and 20 root tabs: 256 visits per tick, every chunk asleep) 6.1 µs, against the 0.5 ms budget. `desktank window --demo-pour 3` 3.8% of a core.
- Random ticks sampled with replacement made decay times spread like a geometric sum; a rotating window over the living lists (each cell visited every ⌈living/budget⌉ ticks) keeps every detritus cell within ±10% of its time even at 12× the budget.
- A current that lets water swap with water is a symmetric random walk for anything carried in it: dye didn't drift at all. Water is the medium and only fills in behind carried cells, which also means a jet through clear water costs no wakes.
- Two seeds of the fertiliser dissolve test differed by 3σ from the mean with 240 cells; acceptance tests on rates use ≥ 960 cells.
- A bubbler that only turns water into bubbles drains the tank (a bubble pops into air); returning the first air cell above each release to water keeps the level exact, at the cost of a small mound over the bubbler.
- A sand pillar can't hold up anything for long: it slumps to its angle of repose. Tests that need a support use a glued rock.
- T6 growth, measured (160×120 tank, aquasoil bed, one cutting): 185–235 plant cells after 10 simulated minutes over seeds 0–5 (stem 42–48, leaves 100–132, roots 43–61), so N = 150. Without CO₂ growth is limited by the per-cell chance, not the visit rate: the plant's few hundred living cells sit well under the 256-visit budget.
- T6 overfeeding: food only fouls the tank after it rots (pellets 600 s to detritus, 180 s more to nutrients), and nutrients spread through the whole tank, so a "big" overfeed must lift the *tank-wide* mean above the algae threshold or the algae dies back by itself once the local plume diffuses. 20 pinches (about 740 pellets) in a 320×180 tank only reached a mean of 0.4 and the algae collapsed before any water change; 40 pinches reach 0.8.
- Algae dying into water (not detritus) avoids a feedback loop: detritus releases 0.5 nutrient per cell, 100× what a cell of algae takes to grow.
- Plant tissue blocking light like rock (opacity 1) shaded a plant's own lower leaves to below the wilt threshold; plant cells now block 0.3 of the light (material `opacity`).
- `powf` at load could differ in the last bit between platforms' maths libraries and flip a random draw, which would break the plant render references across CI platforms; a Newton root with plain arithmetic matches `powf` to 1e-14 and is the same everywhere.
- T6 bench (M3 Max, criterion, same session as main for comparison): heavy pour 1.49 / 1.63 ms (main 1.49 / 1.63 ms), settled 3.6 µs (main 3.5 µs), settled with bodies 3.6 µs (3.5), settled living 5.1 µs (5.3), and a new planted case (the living tank with 16 cuttings grown for 30 minutes) 8.5 µs, against the 0.5 ms budget.
- The `planted` render scene runs 7200 ticks per capture; four captures take under 3 s in the debug test build.
- T6b bench (M3 Max, criterion, same session as `main` at ce86a00): settled 3.52 µs (main 3.54), settled living 5.21 µs (4.96), planted 5.81 µs (8.88), heavy pour 1.61 / 1.67 ms (1.52 / 1.66), and `settled_500_plants` (528 plants, 21,745 cells, every chunk asleep) 11.3 µs against the 0.5 ms budget.
- T6b wider cell texture: `desktank bench --seconds 30` (2560×1440 offscreen) CPU per frame while pouring 2.94 ms mean / 4.36 ms p95 against 2.86 / 4.25 ms on `main` with `Rg8Unorm`; GPU mean 0.016 ms (0.031); RSS 24.1 MB (23.4).
- T6b: without CO₂ injection the species grow at about half their rate (CO₂ `min` below 0), so the `planted` scene's stems are shorter at 6 minutes than T6's; the T6 growth test (≥ 150 cells in 10 minutes) still holds.
- T7b acceptance (20 Hz). Eight tetras released 40 cells apart met the three-body-length mean nearest-neighbour limit on 5,820 and 5,819 of 6,000 ticks (seeds 4 and 77, including convergence). In two ten-minute runs, zone occupancy was 99.7–99.9% for tetras, 98.7% for corydoras, 99.5% for bettas and 96.4% for nerites. A nerite counts as in-zone only when it touches a surface. The four-species collision run covers 100,000 ticks.
- Turned crawlers: a crawler in an inside corner touches two faces, so trying faces in a fixed order flipped it between them each step. It now keeps the face under its foot while that still holds, and keeps its turn at outside corners (diagonal support only) until it finds a face. A turn keeps the foot edge on the face and slides along it by up to the difference in the sprite's sides; if nothing fits there, the old turn stays.
- Script pours with `repeat` build their body one disc per tick, so creatures added on tick 0 next to a long rock arm or sand bed fell before it existed; the `climbing` scene adds its nerites on tick 80.
- Turned nerites (M3 Max, Criterion, same session): settled with fish 8.68 → 7.22 µs and grazing 28.04 → 26.86 µs per tick; the run-to-run spread is wider than any change (neither case has a nerite; a crawler steps every 10 ticks and a turn tries at most 2·|w − h| + 1 boxes).
- T7b Criterion on the M3 Max (640×360, release). The settled tank with ten of each fish took 7.37 µs/tick against T7a's 7.3 µs. A second consecutive grazing tick with a 640-cell film and ten corydoras taking another ten bites took 28.04 µs. Both fit the 500 µs budget.
- On the same M3 Max, release `desktank bench --seconds 60 --fish 30` at 2560×1440 used 1.66% of one core while pouring and settling, then 0.72% over the final 37.8 s (756 frames, zero awake chunks). Peak RSS was 23.9 MiB. A T7a run with the same command measured 4.06%, 2.53% and 23.4 MiB respectively. These are individual process samples on a shared machine.
- T6d cost (M3 Max, release, `desktank bench --fish 30` patched to fill a third of the 2560×1440 screen with leaf cells, wall time of render plus `poll` to GPU completion per frame): p50 2.27 → 2.44 ms, p95 2.80 → 3.07 ms; a plant fragment reads up to about 12 texels against 2 before. A normal tank has far fewer plant pixels. Settled `desktank bench --seconds 40`: 0 frames, 0.16% of a core, RSS 25.0 MB peak, so a settled planted tank costs nothing extra.
- T6d colouration: mixing a yellow-green shade towards a pink-red one goes through a dull tan halfway, so a half-coloured rotala looked beige rather than pink; the shader runs the shift 1.6× ahead of the colouration (clamped) so it saturates. Keep the target's lightness from the shade (scale the colour by luma ratio) or new growth turns dark. Aquasoil buffers the water to 0.4 nutrient and plants don't take nutrients up, so "lean" thresholds sit above 0.4 or no aquasoil tank ever colours.
- Sprites at two texels per cell (D19): an odd cell scale would make texels alternate between ⌊s/2⌋ and ⌈s/2⌉ pixels, so layouts round the scale down to even. At scale 1 the fragment at pixel centre k + 0.5 samples texel 2k + 1, so each pixel shows the lower-right texel of its 2×2 block; hand-drawn icons avoid a 2:1 downsample, which muddied small features such as eyes.
- T8: a loaded tank only continues exactly if everything that feeds a later tick is saved, including state the hash leaves out (body poses, chunk work rects, the random-tick lists' order, the light, which is only recomputed at the next field step). The tests compare re-encoded bytes as well as hashes; zeroing a body's velocity or angle on load was only caught once a test saved while a rock was falling and another was tipping.
- T8: saves of the 640×360 window tank are 18 KiB (encode about 1 ms, write and fsync 10–17 ms on the M3 Max's SSD, on the main thread every 5 minutes). Most of a save is colour noise; XOR with the fresh-tank noise makes untouched water compress to nothing.
- T8: the spec put the ownership lock on the save file, but saves are replaced by renames, which would swap the locked file away; the lock is on `main.lock`. std's `File::try_lock` (Rust 1.89+) does it without `fd-lock`, and the data dir is a few lines of `cfg` without `directories`.
- `desktank bench --fish N` (`scene::stock`) cycles through every swimmer and walker, so from the shrimp PR (#24) 30 creatures are six each of tetra, corydoras, betta, cherry and amano rather than ten each of three fish; bench numbers from before are not directly comparable. From the more-fish PR they are eight species in id order: four each of tetra, corydoras, betta, cherry, amano and honey gourami, three each of guppy and harlequin.
- More fish (M3 Max, release, `desktank bench --seconds 60 --fish 30`, the eight-species mix above): 1.11% of a core while pouring and settling, 0.66% over the settled 37.8 s (756 frames, zero awake chunks; settled sim tick mean 0.016 ms), RSS 25.5 MB peak. The shrimp PR's mix measured 0.72% settled and 23.9 MiB; the new species add only sprite atlas texels and table entries, so the difference is within run-to-run noise on a shared machine.
- A species' swatch (web palette, inspect) is its sprite's commonest colour, so a pattern can take it over: the harlequin's black wedge first outnumbered its copper body and gave it a black swatch. Check the swatch when drawing a strongly marked species.
- Schooling filters schoolmates by species, so two schooling species never steer by each other; the harlequin test checks it exactly by running each species alone with the same creature ids and comparing every creature every tick.
- Plant propagule: `Tools` stores the pick and resolves it against the current species on every read, rather than resetting it on a species change, so picking seeds on hygrophila, passing through rotala (cuttings only) and coming back pours seeds again; hosts show `plant_propagule`, never the stored pick.
- T6c rosettes: blades side by side in adjacent columns drew as one solid trunk at two texels per cell; arching the off-centre blades outwards from their second cell and drawing vallisneria's ribbons one texel wide keeps them apart. A rosette that stopped at its mature size stranded its runners half way (vallisneria reached 200 cells before its left runner rooted), so runners now grow past the size. Measured (160-wide tank, aquasoil, no CO₂): vallisneria roots its first child after 10–12 minutes and a grandchild by 30; a carpet planting spreads to 5+ tufts over 20+ columns in 15 minutes; the amazon sword makes 71–72 cells in 10 minutes on plain aquasoil and 122–123 over a buried root tab (seeds 7, 8). Root feeding is modest because nutrients diffuse through the substrate as through water (the T5/T6 item below), so the bed and the water near it carry the same level.
- T6c bench (M3 Max, criterion, branch and `main` back to back): `settled_500_plants` 11.5 µs with 517 plants of every form and 19,549 cells (main 10.7 µs with 528 stem and mat plants), settled 3.62 µs (3.67), planted 6.22 µs (5.94: the extra part and the root-feeder check in each plant visit), all far under the 0.5 ms budget.
- T6c part 2 bench (M3 Max, criterion, `main` then branch back to back): `settled` 3.74 µs (main 4.46), `planted` 6.69 (7.09), `settled_500_plants` 12.6 (12.8): no cost with no floaters (`update_rafts` returns at once). New: `settled_floaters` 9.1 µs with 234 floaters (2,446 cells) covering the surface, all asleep (each sleeping raft checks its chunks for work every tick), and `drifting_floaters` 27.2 µs a few seconds after a filter outlet starts a surface current (rafts in the jet stepped every tick), all far under the 0.5 ms budget. Measured: under a strip of frogbit the light four rows above the bed is about 58% of open water's; duckweed in a filter outlet's surface jet drifts about 30 cells in 36 s.
- Plant species (ludwigia, cabomba, bacopa, christmas moss): a leaf is two texels tall and leaf rows are a cell apart, so "round" and "oval" are carried by leaf length, stem width and colour rather than outline; a mat is one cell thick (it grows only into water touching what it clings to), so moss texture lives in its 2-texel edge, which is why christmas moss differs from java moss by a regular edge pattern rather than by depth. Measured (seeds 0–1, 10 minutes alone, open / under a 5-row lid): ludwigia 135 / 110 cells, cabomba 218–225 / 66–67 (light-limited), bacopa 104 / 99–100.
- T9 part 1: criterion `settled_with_fish` (30 fish, M3 Max, back to back with `main`) 7.37 µs/tick against 7.13 µs: ageing, energy and the once-a-second water-quality sample (3600 field cells and the plant table; the grid only where cells changed) cost about 0.24 µs. The bench now tops the fish's energy up every 100,000 ticks: criterion runs past the 8-hour reserve, and starved fish made it read 3.6 µs. `settled` 3.49 µs (3.50), `grazing` 26.8 µs (26.7), `settled_living` 5.26 µs (5.18). `desktank bench --seconds 40 --fish 30` (2560×1440): settled 3.32% of a core (main 3.31%), settled tick mean 0.048 ms (0.049), RSS 25.7 MB peak (25.7).
- T9 part 2: eggs first went on any water cell near the mother, so a clutch laid in mid water hung there (they are solid cells) and eggs written under another creature left it overlapping a solid for a tick (the `no_creature_enters_a_solid_cell` test caught it); eggs now stick to a surface or sink to the bed below her, never under a creature. Cream eggs were invisible on sand, hence amber.
- T9 part 2: once creatures pair, every long-running test or bench that assumed a fixed population needs all males, easy mode or a cap at the population; `settled_with_fish` now caps the tank at its 30 fish (the females check every minute and never conceive).
- T9 part 2: criterion `settled_with_fish` (M3 Max, back to back with `main`) 7.75 µs/tick against 7.52 µs (the per-tick breeding countdown and the once-a-minute and once-a-second checks); `settled` 3.55 (3.52), `grazing` 27.6 (27.5), `settled_living` 5.33 (5.18), `settled_500_plants` 11.4 (11.1). `desktank bench --seconds 40 --fish 30` (2560×1440, two runs each, alternating): settled 2.67–3.00% of a core (main 2.42–2.75%; this machine's run-to-run noise is about as large), settled tick mean 0.062–0.070 ms (0.058–0.066), RSS 26.0 MB peak (25.6–25.8); a predator eats one of the 30 within the 40 s (the bench stocks every non-crawler species, cherry shrimp and guppies included).
- T10 catch-up (M3 Max, release, `desktank bench --catch-up`). Across three seeds, 24 h took 9.98–10.38 ms for catch-up (seed medians) and 16.77–17.72 s for full simulation. The 160×90 tank started with 7 creatures and 14–15 rotala cells. Both paths ended with 68–82 creatures including 28–45 fry, 62–76 births and one old-age death per seed. Catch-up averaged 711.33 plant cells against 780 (−8.80%) and 0.88796 mean nutrient against 0.79478 (+11.72%). Catch-up groups ecology into five-minute steps with minute breeding checks and caps diffusion while applying the full elapsed decay. Creatures eat available food and grazing cells across the tank. Corpses rot in place. The model skips movement, device activity, current, waste, predation, live-food feeding and air-breathing checks.
- T9: grazers live off algae and detritus, so in a clean tank otocinclus, nerites and shrimp starve after 8 hours of world time unless fed wafers or pellets, as in life; the clean-up crew needs a tank that grows something.
- T9: a water-quality sample that is exact but only recounts changed field cells must also count edits made since the last refresh (`changed_next`), or a loaded tank (whose counts start from scratch) would diverge from one that kept running.
- D21: with `BAND_REACH` 1, a stand of stem plants four cells apart (leaves interlocking) is still a wall in every band; fish reach food lodged in it from the open sides, not through it. With 0 plants hardly block at all, with 2 a planted tank is solid again. A dodge must hold still while it shifts: a fish that kept sliding along the plant reached the new band somewhere it didn't fit and gave up, and re-picking the nearest band each tick made it flip between two targets forever.
- D21: criterion (M3 Max, interleaved with `main`, machine under load): `settled_with_fish` 8.40–8.54 µs/tick against 7.47–7.59 (open water, no plants: depth easing, wandering bands and the blocked-move checks), new `plants_with_fish` (500 plants, 30 swimmers) 19.6–19.7 µs against 16.2–16.4 (plant band lookups, memoised per plant within a body box); `planted` 6.03 (6.07) and `settled_500_plants` 11.09 (11.12) unchanged. All far inside the 0.5 ms settled budget.
- D21: plant bands are derived from the seed, plant id and the cell's place in the plant (a table lookup per plant cell a creature's box meets), so they cost no cell bits and no save field; a fragment or runner-rooted child gets a new id and so a new band, and a creature caught inside it shifts band or hops out.
- D21 part 2 bench (M3 Max, release, `desktank bench --seconds 40 --fish 30`, 2560×1440, wall time of `render_to` plus `poll` to GPU completion per frame, `main` and branch interleaved; the machine was busy and `main` alone varied 2× between runs): plain tank p50 2.18 → 2.37 ms, p95 3.20 → 3.22 ms; settled CPU 3.04% → 3.08% of a core. - Blinker: a 30×22-cell body makes the shared tests' fixed spawn grids too crowded (they place one blinker where it fits), and its 60-texel frames leave 16 texels of each 256-texel atlas row empty. Glow costs nothing by day: the halo quad grows and the neighbour taps run only when the darkness and the creature's strength are both above zero. Measured (M3 Max, release, a temporary bench patch adding 10 blinkers to `desktank bench --seconds 20 --fish 30` at 2560×1440, scale 4, two interleaved runs each): per-frame wall time to GPU completion 3.62 / 3.67 ms at noon against 3.74 / 3.59 ms at midnight, CPU 7.2–7.5% against 7.3–7.6%: the halo's up to 49 taps per transparent fragment don't show.
- CI path filters: GitHub reports a skipped matrix job as one check named `matrix.os` rather than one per OS, so require `ci-ok`, not the per-job checks. Runs on `main` diff only against the previous commit, so they are no longer cancelled by the next push (`cancel-in-progress` is for PRs only).
- Crabs: a species key that is off by default (`waste_every`, `eats_corpses`, `home_carpet`, `cheat_only`) keeps every existing tank, hash and reference image as it was; per-creature state that only some species use is hashed only when set, so the pinned v2 to v4 fixture hashes didn't move.
- Hunting and territory: a chase or a homing territory steers at one point, so a plant wall between them is a trap: the betta dodged bands in place for 390 s in the depth test's planted tank. A blocked chase must be given up, and a territorial fish blocked outside its territory needs a way out (it settles a new one). Fry fleeing to the nearest plant cell were caught among sparse leaves that weren't cover, and died more often than in the open (8 against 27 of 36 left); seeking the middle of a five-cell run down a stem or blade, cover by itself, turned that round (11 against 2). Any test that puts a predator with something it could eat (an adult guppy with fry, a betta with crabs or shrimp) now has a hunt in it: use easy mode or keep them apart.
- Hunting and territory bench (M3 Max, criterion, `main` then branch back to back, 2 s warm-up, 8 s measurement; measured before the rebase onto plant colouration and filter-carried bubbles, #70 and #73): `settled_with_fish` (neons, corydoras and bettas: two territories) 8.35 → 9.03 µs/tick, `plants_with_fish` (with guppies, bettas and gouramis) 23.65 → 25.31 µs, `settled` 3.56 → 3.58, `settled_living` 5.26 → 5.32: the per-tick snapshot and the once-per-10-ticks look round, far inside the 0.5 ms budget. No render or frame-pacing change.
- Bigger betta: stocked species stay within 16 cells a side (`builtin_species_load`, and the spawn grids in `tests/depth.rs` and the shared test tanks), except the halfmoon betta at 20×16 cells: its fins reach 4 cm past its 6 cm body. A 22×19-cell photo-scale draft broke the shallow predator tanks and let its territory patrols reach mid-water, so the fins are drawn in a relaxed spread (scaled to 0.8 about a shared centre so they stay one drape). `desktank_sim::scene::stock` silently skips a species whose body doesn't fit, so a tank under about 24 rows of water gets no betta. A size change also moves any test tank that stocks every species, so check the save fixtures' replays. Large art also costs atlas rows: creature looks are shelf-packed, tallest first, to stay inside WebGL2's 2048 texels, and a species has at most 8 morphs (`MAX_MORPHS`).
- Floaters' hanging roots are soft (`World::blocks_with` with `soft`; the plant's form is read through the `PlantDepth` memo, so it costs nothing extra per cell). Swimmers, walkers and sinking corpses pass through them in any band; the renderer still draws root cells by the plant's band, so a fish behind the floater's band shows through its roots and one in front shows over them. Surface crawlers keep them solid so snails and micro crabs still climb them (`World::blocks`, which `supported` uses, is unchanged). Roots already counted as cover (`in_cover` counts plant cells around the body); now a fleeing fish can also slip in among them, so prey hides in a floater's roots as real fry do in frogbit. Every corpse, a crawler's included, sinks through them. Before this, a dense duckweed mat whose per-plant root bands covered all eight bands across a fish's width walled guppies off from every frond.
- Devices (DV1–DV2, D27): the device table must be restored before `load_life`, which works out the current and wakes the fields; restoring it after (and recomputing) would leave the fields' wake state different from the saved tank's, so it wouldn't continue exactly. A loaded v12 device must match its grid cells (each footprint cell a `device` cell holding its id), which also rules out overlapping footprints. DV2 replaced the 1D horizontal jet with an obstacle- and wall-aware incompressible 2D vector field (directed nozzles and radial intake sinks projected on a 1/8-res MAC grid with zero normal flow on walls and solid/air blocks, rendered in the Flow overlay with a vector texture at binding 9, now `Rgba8Unorm` with the sway lean in `b`, #186), retuned the jet/floater/marimo/bubble/overlay tests onto `InternalFilter` without legacy `filter_outlet` blobs, and tracks carryable cells (`CARRYABLE`: floaters, non-water dense liquids, powders with density < 1.5) and open/blocked state per 8×8 block so settled tanks perform zero rebuilds and zero `run_current` scans. Rising bubble deflection in `Pass::Rise` uses the per-tick chunk RNG (`rngs[ci]`) rather than `life.rng`, which is only re-seeded in `after_tick` and not persisted in saves.
- Pixel probes in offscreen render tests: at scale 1 a sprite pixel spans 2×2 coarse texels and its centre lands exactly on a texel boundary, so lavapipe (Linux CI) and Metal can pick different texels there (DV1's filter test read a blue slot vent on Linux and the plastic beside it on macOS). Probe a cell whose 3×3 cell neighbourhood is one colour in the art, or render at a scale where texel centres fall inside pixels.
- Windows DX12 draws with the split grid. wgpu's default DX12 compiler is FXC (DXC only if `dxcompiler.dll` is on the PATH or `static-dxc` is built in), and after the algae coat (#178) FXC miscompiled the one-pass `fs_main` without an error: plant art lost its leaves and the water striped, on the CI's WARP adapter and so presumably for users. It was shape-sensitive: one commit broke only the sRGB pipeline, the next none, the next every scene. DXC drew every scene right, and so did FXC with the split grid, whose smaller shaders it compiles correctly. `Gpu::new` turns the split grid on for a DX12 adapter; a move to DXC (static or shipped) would let Windows go back to one pass.
