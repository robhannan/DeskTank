# Desktop packaging and identity (P1)

## Windows distribution

1. **Can an unpackaged process set the lock-screen image? Yes.** The linked Windows PowerShell implementation opens a local image as a WinRT `StorageFile`, calls `LockScreen.SetImageFileAsync` and waits for completion in the user's session. This is evidence for an unpackaged caller. Microsoft's method contract describes the operation but makes no promise that a policy-managed lock screen or Spotlight will display the result. L2 should verify the visible change and restoration with Picture selected. [PowerShell implementation](https://github.com/okieselbach/Intune/blob/master/Set-Lockscreen.ps1) · [Microsoft API](https://learn.microsoft.com/en-us/uwp/api/windows.system.userprofile.lockscreen.setimagefileasync)
2. **Ship an MSI? Yes. Require MSIX? No.** Keep the existing cargo-dist MSI plan. L2's API can be called from the ordinary desktop process, and the elevated installer can place the saver in the system directory. Package identity buys neither capability for this design. [Distribution plan](../spec/architecture.md#8-distribution)
3. **Can the saver be installed per user and per machine? Yes.** The MSI places the native-architecture `.scr` in the Windows system directory for machine-wide discovery. For a single account, keep the binary in a stable user-local directory and pass its absolute path to `desk.cpl,InstallScreenSaver`. The selected saver is recorded in `HKCU\Control Panel\Desktop\SCRNSAVE.EXE`. Selection is per user even with a system-wide binary. Group Policy can override it. Do not promise that the picker enumerates arbitrary user folders. [Selection and activation](https://learn.microsoft.com/en-us/windows/win32/devnotes/scrnsave-exe) · [Saver discovery](https://learn.microsoft.com/en-us/windows/win32/lwef/screen-saver-library) · [Microsoft's System32 example](https://learn.microsoft.com/en-us/windows/win32/controls/themesfileformat-overview)

## macOS bundle and permissions

4. **Does a Rust cdylib load as a saver bundle executable? Yes, at the bundle loader boundary.** On arm64 macOS 27.2.1 (26B131), we compiled an empty Objective-C `P1SaverView : ScreenSaverView` subclass to `class.o`, then linked it into a Rust library with `rustc --crate-type cdylib probe.rs -C link-arg=class.o -l framework=ScreenSaver -l framework=AppKit`. We put the resulting arm64 Mach-O shared library in `Probe.saver/Contents/MacOS/Probe` and set `CFBundleExecutable=Probe`, `CFBundlePackageType=BNDL` and `NSPrincipalClass=P1SaverView` in Contents/Info.plist. A separate ScreenSaver-linked process obtained an NSBundle for that path. Both `[bundle load]` and `[bundle.principalClass isSubclassOfClass:ScreenSaverView.class]` returned 1. No relink with `-bundle` was needed. The probe did not exercise System Settings, quarantine or the legacy host's animation lifecycle.
5. **Does reading modifier flags require a permission grant? No on the tested system.** We ad-hoc signed a fresh background app and launched it with Launch Services. Both `AXIsProcessTrusted()` and `CGPreflightListenEventAccess()` returned false. It sampled `CGEventSourceFlagsState(kCGEventSourceStateCombinedSessionState)` at 10 Hz while a separate process posted Shift down and up. The Shift bit (0x20000) went clear → set → clear. The app only queried flags. This observation is specific to the aggregate modifier API on that macOS build.
6. **Are other windows' bounds available without Screen Recording permission? Yes.** In the same app, `CGPreflightScreenCaptureAccess()` returned false. Nine on-screen entries owned by other processes supplied `kCGWindowBounds` via `CGWindowListCopyWindowInfo(kCGWindowListOptionOnScreenOnly, kCGNullWindowID)`. Compare bounds with the relevant display in screen coordinates. A display-sized ordinary window can match too. Apple identifies window names and sharing state as restricted metadata. [Apple WWDC session](https://developer.apple.com/videos/play/wwdc2019/701/?time=1460)

## Windows overlay and power

7. **Does wgpu DX12 support a premultiplied composition swap chain? Yes.** In the locked 30.0.2 backend, select `Dx12SwapchainKind::DxgiFromVisual` for the HWND. The adapter advertises `CompositeAlphaMode::PreMultiplied` on that target and the surface uses `CreateSwapChainForComposition`. The default `DxgiFromHwnd` target advertises only opaque alpha. Supply premultiplied pixel values. [Swap-chain options](https://docs.rs/wgpu-types/30.0.2/wgpu_types/enum.Dx12SwapchainKind.html) · [DX12 capabilities](https://docs.rs/crate/wgpu-hal/30.0.2/source/src/dx12/adapter.rs) · [Presentation implementation](https://docs.rs/crate/wgpu-hal/30.0.2/source/src/dx12/mod.rs)
8. **Can the layered, transparent HWND remain click-through with no redirection bitmap and DirectComposition? Yes in a published implementation.** Its top-level HWND combines all three styles and `WS_EX_NOACTIVATE`, with a no-cursor class and `HTTRANSPARENT` hit-test response. Microsoft documents mouse pass-through for transparent layered windows. The reference implementation supplies evidence for the combined composition path. O1-Win should present visible tank pixels over a second process, click both opaque and clear regions, then verify that interact mode receives clicks and toggles back. [Overlay window implementation](https://github.com/qdzsh/overlay-compositor/blob/7c20fdf4f779b9bcbb248d1b70ded87a5fffeb85/src/main.cpp) · [Microsoft layered-window hit testing](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#layered-windows)
9. **Is there an energy saver status notification? Yes.** Register for `GUID_ENERGY_SAVER_STATUS` on Windows 11 build 26100+ (24H2). Its DWORD distinguishes off, standard and high savings. Either active state pauses rendering under §6.2. On older supported builds use `GUID_POWER_SAVING_STATUS` (battery saver, DWORD 0/1). Microsoft's sample specifies the build floor for the newer signal. [Power setting GUIDs](https://learn.microsoft.com/en-us/windows/win32/power/power-setting-guids) · [Microsoft registration sample](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/powersettingregisternotification/)

The Windows findings come from API documentation and implementation sources. No Windows desktop session was exercised for P1.
